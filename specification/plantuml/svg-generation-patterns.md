## Architecture Overview

### Multi-Layer Rendering Architecture

PlantUML uses a sophisticated multi-layer architecture for SVG generation:

```
┌─────────────────────────────────────┐
│  Diagram-Specific Logic             │
│  (Activity, Sequence, Class, etc.)  │
└──────────────┬──────────────────────┘
               │
┌──────────────▼──────────────────────┐
│  UGraphic Abstraction Layer         │
│  (Platform-independent drawing API)  │
└──────────────┬──────────────────────┘
               │
┌──────────────▼──────────────────────┐
│  Driver System                       │
│  (Shape-specific renderers)          │
└──────────────┬──────────────────────┘
               │
┌──────────────▼──────────────────────┐
│  SvgGraphics Core                    │
│  (Direct SVG DOM manipulation)       │
└──────────────┬──────────────────────┘
               │
┌──────────────▼──────────────────────┐
│  XML Serialization                   │
│  (Final SVG output)                  │
└─────────────────────────────────────┘
```

### Key Java Classes

| Class | Location | Purpose |
|-------|----------|---------|
| `SvgGraphics` | `klimt/drawing/svg/` | Core SVG DOM builder |
| `UGraphicSvg` | `klimt/drawing/svg/` | High-level graphics context |
| `UGroupType` | `klimt/` | Defines semantic group metadata |
| `SvekNode` | `svek/` | Entity wrapper for positioning |
| `SvekEdge` | `svek/` | Link/relationship renderer |
| `GeneralImageBuilder` | `svek/` | Factory for entity images |

## Core SVG Structure

### Root SVG Element

Every PlantUML SVG follows this structure:

```xml
<svg xmlns="http://www.w3.org/2000/svg"
     xmlns:xlink="http://www.w3.org/1999/xlink"
     version="1.1"
     viewBox="0 0 {maxX} {maxY}"
     preserveAspectRatio="{option}"
     contentStyleType="text/css">

  <!-- Optional title and description -->
  <title>PlantUML Diagram</title>
  <desc>Generated by PlantUML</desc>

  <!-- Definitions section -->
  <defs>
    <!-- Gradients, filters, styles, scripts -->
  </defs>

  <!-- Main content group -->
  <g>
    <!-- All diagram elements -->
  </g>

  <!-- Metadata comment -->
  <!--SRC=[{encodedSource}]-->
</svg>
```

### Coordinate System

- **Origin**: Top-left (0, 0)
- **X-axis**: Increases rightward
- **Y-axis**: Increases downward
- **Scaling**: All coordinates scaled by `option.getScale()`

## Metadata and Grouping

### UGroupType Enum

PlantUML defines **semantic group types** that map to SVG attributes:

| UGroupType | SVG Attribute | Purpose |
|------------|---------------|---------|
| `ID` | `id` | Element identifier |
| `CLASS` | `class` | CSS class name |
| `TITLE` | `title` | Tooltip text |
| `DATA_ENTITY` | `data-entity` | Entity name |
| `DATA_QUALIFIED_NAME` | `data-qualified-name` | Fully qualified name |
| `DATA_ENTITY_1` | `data-entity-1` | First entity in relationship |
| `DATA_ENTITY_2` | `data-entity-2` | Second entity in relationship |
| `DATA_ENTITY_UID` | `data-entity-uid` | Entity unique ID |
| `DATA_ENTITY_1_UID` | `data-entity-1-uid` | First entity UID in link |
| `DATA_ENTITY_2_UID` | `data-entity-2-uid` | Second entity UID in link |
| `DATA_PARTICIPANT` | `data-participant` | Sequence diagram participant |
| `DATA_PARTICIPANT_1` | `data-participant-1` | First participant in message |
| `DATA_PARTICIPANT_2` | `data-participant-2` | Second participant in message |
| `DATA_UID` | `data-uid` | Unique identifier |
| `DATA_SOURCE_LINE` | `data-source-line` | Source line number |

### Standard Group Pattern

**Java Code** (from EntityImageClass.java):
```java
final UGroup group = new UGroup(getEntity().getLocation());
group.put(UGroupType.CLASS, "entity");
group.put(UGroupType.ID, "entity_" + getEntity().getName());
group.put(UGroupType.DATA_ENTITY, getEntity().getName());
group.put(UGroupType.DATA_UID, getEntity().getUid());
group.put(UGroupType.DATA_QUALIFIED_NAME, getEntity().getQuark().getQualifiedName());
ug.startGroup(group);
// Draw entity content
ug.closeGroup();
```

**Resulting SVG**:
```xml
<g class="entity"
   id="entity_MyClass"
   data-entity="MyClass"
   data-uid="0001"
   data-qualified-name="com.example.MyClass">
   <!-- Entity content -->
</g>
```

## Diagram-Specific Patterns

### Activity Diagrams

**Package**: `activitydiagram3/`

#### Entity Types
- Activities (rounded rectangles or octagons)
- Start/end nodes (circles)
- Decision nodes (diamonds)
- Synchronization bars (rectangles)
- Swimlanes/partitions

#### SVG Structure Pattern

```xml
<g id="activity_{id}">
  <!-- Rounded rectangle for activity -->
  <rect x="{x}" y="{y}"
        width="{width}" height="{height}"
        rx="{cornerRadius}" ry="{cornerRadius}"
        fill="{color}"
        stroke="{borderColor}"
        style="..."/>

  <!-- Activity label -->
  <text x="{cx}" y="{cy}"
        text-anchor="middle"
        font-family="{font}"
        font-size="{size}">
    {activityName}
  </text>
</g>
```

#### Shape Types
- **Activities**: `ShapeType.ROUND_RECTANGLE` or `ShapeType.OCTAGON`
- **Decisions**: `ShapeType.DIAMOND`
- **Start/End**: `ShapeType.CIRCLE`

#### Key Features
- Rounded corners via `rx`, `ry` attributes
- Shadows via SVG filters (see [Shadows](#shadows))
- URL links with `<a xlink:href="...">` wrapper

#### Detection Strategy

Look for:
- Multiple rounded rectangles (`<rect>` with `rx` > 0)
- Diamond shapes (`<polygon>` with 4 points)
- Circle start/end nodes (`<ellipse>` or `<circle>`)
- Flow arrows (`<path>` elements connecting nodes)

---

### Sequence Diagrams

**Package**: `sequencediagram/`
**Rendering Engines**: PUMA or Teoz

#### Architecture Differences
- **Does NOT use SVEK** (no Graphviz layout)
- Direct coordinate calculation
- Component-based rendering ("skin" system)

#### Entity Types
- Participants (actors, entities, boundaries, etc.)
- Lifelines (vertical dashed lines)
- Messages (arrows between participants)
- Activation boxes (rectangles on lifelines)
- Groups (boxes for alt/opt/loop/par)

#### SVG Structure Pattern

**Participant**:
```xml
<g data-participant="{participantName}">
  <!-- Participant box (head) -->
  <rect x="{x}" y="{y}"
        width="{width}" height="{height}"
        fill="{color}" stroke="{borderColor}"/>

  <!-- Participant label -->
  <text x="{cx}" y="{cy}" text-anchor="middle">
    {participantName}
  </text>

  <!-- Lifeline -->
  <line x1="{cx}" y1="{y+height}"
        x2="{cx}" y2="{bottomY}"
        stroke-dasharray="5,5"/>
</g>
```

**Message**:
```xml
<g data-participant-1="{source}"
   data-participant-2="{target}">
  <!-- Arrow line -->
  <path d="M {x1},{y1} L {x2},{y2}"
        stroke="{color}"/>

  <!-- Arrowhead -->
  <polygon points="{x2},{y2} ..." fill="{color}"/>

  <!-- Message label -->
  <text x="{mx}" y="{my-5}">
    {messageText}
  </text>
</g>
```

#### Key Attributes
- `data-participant`: Participant name
- `data-participant-1`: Message source
- `data-participant-2`: Message target

#### Detection Strategy

Look for:
- Groups with `data-participant` attributes
- Vertical dashed lines (lifelines)
- Horizontal arrows between participants
- `data-participant-1` and `data-participant-2` on message groups

### Class Diagrams

**Package**: `classdiagram/`
**Entity Image**: `svek/image/EntityImageClass.java`
**Uses**: SVEK engine (Graphviz layout)

#### SVG Structure Pattern

```xml
<g class="entity"
   id="entity_{className}"
   data-entity="{className}"
   data-uid="{uid}"
   data-qualified-name="{package.className}">

  <!-- Class header -->
  <rect x="{x}" y="{y}"
        width="{width}" height="{headerHeight}"
        fill="{headerColor}" stroke="{borderColor}"/>
  <text x="{x+padding}" y="{y+textOffset}">
    «{stereotype}»
  </text>
  <text x="{x+padding}" y="{y+nameOffset}" font-weight="bold">
    {className}
  </text>

  <!-- Separator line -->
  <line x1="{x}" y1="{y+headerHeight}"
        x2="{x+width}" y2="{y+headerHeight}"/>

  <!-- Fields section -->
  <rect x="{x}" y="{y+headerHeight}"
        width="{width}" height="{fieldsHeight}"
        fill="{bodyColor}"/>
  <text x="{x+padding}" y="{y+headerHeight+lineHeight}">
    {visibility} {fieldName}: {fieldType}
  </text>
  <!-- More fields... -->

  <!-- Separator line -->
  <line x1="{x}" y1="{y+headerHeight+fieldsHeight}"
        x2="{x+width}" y2="{y+headerHeight+fieldsHeight}"/>

  <!-- Methods section -->
  <rect x="{x}" y="{y+headerHeight+fieldsHeight}"
        width="{width}" height="{methodsHeight}"
        fill="{bodyColor}"/>
  <text x="{x+padding}" y="{y+headerHeight+fieldsHeight+lineHeight}">
    {visibility} {methodName}({params}): {returnType}
  </text>
  <!-- More methods... -->
</g>
```

#### Visibility Symbols
- `+` : Public
- `-` : Private
- `#` : Protected
- `~` : Package

#### Relationships

**Association/Inheritance/Dependency**:
```xml
<g data-entity-1-uid="{sourceUID}"
   data-entity-2-uid="{targetUID}">
  <!-- Arrow path -->
  <path d="M {x1},{y1} L {x2},{y2}"
        stroke="{color}"
        fill="none"/>

  <!-- Arrowhead (inheritance) -->
  <polygon points="{x2},{y2} {x2-10},{y2-5} {x2-10},{y2+5}"
           fill="white" stroke="{color}"/>

  <!-- Multiplicity labels -->
  <text x="{x1+offset}" y="{y1-5}">1</text>
  <text x="{x2-offset}" y="{y2-5}">*</text>

  <!-- Role names -->
  <text x="{mx}" y="{my-5}">{roleName}</text>
</g>
```

#### Detection Strategy

Look for:
- Groups with `class="entity"`
- `data-entity` attribute with class name
- `data-qualified-name` for package information
- Rectangular shapes with horizontal separator lines
- Relationship groups with `data-entity-1-uid` and `data-entity-2-uid`

### Component Diagrams

**Package**: `descdiagram/` (Description Diagrams)
**Entity Image**: `svek/image/EntityImageDescription.java`

#### Symbol System

Components use `USymbol` to determine visual representation:

| Symbol | Shape | Usage |
|--------|-------|-------|
| `COMPONENT` | Rectangle with tabs | Components |
| `INTERFACE` | Circle or rectangle with circle | Interfaces |
| `PACKAGE` | Folder shape | Packages |
| `NODE` | 3D box | Deployment nodes |
| `HEXAGON` | Hexagon | Custom shapes |

#### SVG Structure Pattern

**Component**:
```xml
<g class="entity"
   id="entity_{componentName}"
   data-entity="{componentName}"
   data-uid="{uid}">

  <!-- Component rectangle -->
  <rect x="{x}" y="{y}"
        width="{width}" height="{height}"
        fill="{color}" stroke="{borderColor}"/>

  <!-- Component symbol (tabs) -->
  <rect x="{x-5}" y="{y+10}"
        width="30" height="15"
        fill="{color}" stroke="{borderColor}"/>
  <rect x="{x-5}" y="{y+30}"
        width="30" height="15"
        fill="{color}" stroke="{borderColor}"/>

  <!-- Component label -->
  <text x="{cx}" y="{cy}" text-anchor="middle">
    {componentName}
  </text>
</g>
```

**Interface (Lollipop)**:
```xml
<g data-entity="{interfaceName}">
  <!-- Lollipop stick -->
  <line x1="{cx}" y1="{cy}"
        x2="{cx}" y2="{cy-radius-20}"/>

  <!-- Lollipop circle -->
  <circle cx="{cx}" cy="{cy-radius-20}"
          r="10"
          fill="white" stroke="{color}"/>

  <!-- Interface name -->
  <text x="{cx+15}" y="{cy-radius-20}">
    {interfaceName}
  </text>
</g>
```

#### Detection Strategy

Look for:
- Rectangles with small rectangular "tabs" (component symbol)
- Circles connected to components (interfaces)
- 3D box shapes (nodes)
- Folder shapes (packages)

### State Diagrams

**Package**: `statediagram/`
**Entity Image**: `svek/image/EntityImageState.java`

#### Entity Types
- States (rounded rectangles with optional internal content)
- Start state (filled circle)
- End state (bull's eye - circle within circle)
- Transitions (arrows with labels)
- Composite states (states containing substates)
- Fork/Join nodes (horizontal/vertical bars)

#### SVG Structure Pattern

**Simple State**:
```xml
<g id="{stateId}">
  <!-- State body -->
  <rect x="{x}" y="{y}"
        width="{width}" height="{height}"
        rx="{cornerRadius}" ry="{cornerRadius}"
        fill="{color}" stroke="{borderColor}"/>

  <!-- State name -->
  <text x="{x+padding}" y="{y+textOffset}" font-weight="bold">
    {stateName}
  </text>

  <!-- Optional: Horizontal separator -->
  <line x1="{x}" y1="{y+nameHeight}"
        x2="{x+width}" y2="{y+nameHeight}"/>

  <!-- Optional: Internal transitions -->
  <text x="{x+padding}" y="{y+nameHeight+lineHeight}">
    entry / {action}
  </text>
  <text x="{x+padding}" y="{y+nameHeight+lineHeight*2}">
    exit / {action}
  </text>
</g>
```

**Start State**:
```xml
<circle cx="{cx}" cy="{cy}" r="10" fill="black"/>
```

**End State**:
```xml
<g>
  <!-- Outer circle -->
  <circle cx="{cx}" cy="{cy}" r="11"
          fill="white" stroke="black" stroke-width="1"/>
  <!-- Inner filled circle -->
  <circle cx="{cx}" cy="{cy}" r="6" fill="black"/>
</g>
```

**Transition**:
```xml
<g>
  <!-- Transition arrow -->
  <path d="M {x1},{y1} L {x2},{y2}"
        stroke="{color}" fill="none"/>
  <polygon points="{x2},{y2} ..." fill="{color}"/>

  <!-- Transition label -->
  <text x="{mx}" y="{my-5}">
    {event} [{guard}] / {action}
  </text>
</g>
```

#### Detection Strategy

Look for:
- Rounded rectangles with state names
- Small filled circles (start state)
- Bull's eye circles (end state)
- Curved arrows with labels (transitions)
- Horizontal lines within rectangles (separating name from internal content)

## Common SVG Elements

### Drawing Primitives

#### Rectangles

```xml
<rect x="{x}" y="{y}"
      width="{width}" height="{height}"
      rx="{cornerRadius}" ry="{cornerRadius}"
      fill="{color}"
      stroke="{borderColor}"
      stroke-width="{width}"
      style="..."/>
```

**Rounded Corners**: `rx` and `ry` attributes (typically same value)

#### Ellipses and Circles

```xml
<!-- Ellipse -->
<ellipse cx="{cx}" cy="{cy}"
         rx="{radiusX}" ry="{radiusY}"
         fill="{color}"
         stroke="{borderColor}"/>

<!-- Circle -->
<circle cx="{cx}" cy="{cy}" r="{radius}"
        fill="{color}"
        stroke="{borderColor}"/>
```

#### Paths

```xml
<path d="M {x1},{y1} L {x2},{y2} C {cx1},{cy1} {cx2},{cy2} {x3},{y3} Z"
      stroke="{color}"
      stroke-width="{width}"
      fill="{fillColor}"/>
```

**Path Commands**:
- `M x,y` : Move to (absolute)
- `m dx,dy` : Move to (relative)
- `L x,y` : Line to (absolute)
- `l dx,dy` : Line to (relative)
- `C x1,y1 x2,y2 x,y` : Cubic Bézier curve (absolute)
- `c dx1,dy1 dx2,dy2 dx,dy` : Cubic Bézier curve (relative)
- `Q x1,y1 x,y` : Quadratic Bézier curve (absolute)
- `A rx,ry rotation large-arc sweep x,y` : Arc (absolute)
- `Z` : Close path

#### Polygons

```xml
<polygon points="{x1},{y1} {x2},{y2} {x3},{y3} {x4},{y4}"
         fill="{color}"
         stroke="{borderColor}"
         stroke-width="{width}"/>
```

**Diamond Shape** (decision node):
```xml
<polygon points="{cx},{cy-h} {cx+w},{cy} {cx},{cy+h} {cx-w},{cy}"/>
```

#### Text

```xml
<text x="{x}" y="{y}"
      font-family="{fontFamily}"
      font-size="{size}"
      font-weight="{weight}"
      font-style="{style}"
      text-decoration="{decoration}"
      text-anchor="{anchor}"
      fill="{color}">
  {textContent}
</text>
```

**Text Anchor Values**:
- `start` : Left-aligned
- `middle` : Center-aligned
- `end` : Right-aligned

### Styling

#### Colors

PlantUML uses hex color format:
- **6-digit**: `#RRGGBB` (e.g., `#FF0000` = red)
- **8-digit**: `#RRGGBBAA` (last 2 digits = alpha/opacity)
- **Transparent**: `#00000000` or `none`

#### Stroke Styling

```xml
style="stroke:{color};stroke-width:{width};stroke-dasharray:{dash};"
```

**Dash Patterns**:
- `"5,5"` : Dashed line (5px dash, 5px gap)
- `"10,5"` : Long dashes
- `"2,2"` : Dotted line

#### Fill Styling

```xml
fill="{color}"
fill-opacity="{opacity}"
```

Or for gradients:
```xml
fill="url(#gradient_id)"
```

### Special Effects

#### Shadows

PlantUML creates shadows using SVG filters:

```xml
<defs>
  <filter id="f{seed}">
    <feGaussianBlur in="SourceAlpha" stdDeviation="2"/>
    <feOffset dx="4" dy="4" result="offsetblur"/>
    <feComponentTransfer>
      <feFuncA type="linear" slope="0.4"/>
    </feComponentTransfer>
    <feMerge>
      <feMergeNode/>
      <feMergeNode in="SourceGraphic"/>
    </feMerge>
  </filter>
</defs>

<!-- Apply shadow -->
<rect ... filter="url(#f{seed})"/>
```

**Shadow Detection**: Look for `filter="url(#...)"` attributes

#### Gradients

```xml
<defs>
  <linearGradient id="g{seed}"
                  x1="0%" y1="0%"
                  x2="100%" y2="100%">
    <stop offset="0%" stop-color="{color1}"/>
    <stop offset="100%" stop-color="{color2}"/>
  </linearGradient>
</defs>

<!-- Apply gradient -->
<rect ... fill="url(#g{seed})"/>
```

**Gradient Detection**: Look for `fill="url(#g...)"` references

### Hyperlinks

```xml
<a xlink:href="{url}"
   xlink:title="{tooltip}"
   target="{target}">
  <!-- Clickable content -->
</a>
```

**Detection**: Wrapped elements become clickable links

### Transformations

```xml
<g transform="translate({x},{y})">
  <!-- Translated content -->
</g>

<g transform="scale({sx},{sy})">
  <!-- Scaled content -->
</g>

<g transform="rotate({angle},{cx},{cy})">
  <!-- Rotated content -->
</g>
```

**Multiple Transformations**:
```xml
<g transform="translate({x},{y}) scale({s}) rotate({a})">
```

## Parser Implementation Guide

### Essential Parsing Rules

#### 1. Entity Identification

**Priority 1 - Look for data attributes**:
```javascript
const entityGroups = svg.querySelectorAll('g[data-entity]');
const entityUID = group.getAttribute('data-entity-uid');
const entityName = group.getAttribute('data-entity');
const qualifiedName = group.getAttribute('data-qualified-name');
```

**Priority 2 - Look for class attribute**:
```javascript
const entities = svg.querySelectorAll('g[class="entity"]');
```

**Priority 3 - Look for ID patterns**:
```javascript
const stateGroups = svg.querySelectorAll('g[id^="state_"]');
const activityGroups = svg.querySelectorAll('g[id^="activity_"]');
```

#### 2. Link Identification

**Look for endpoint UIDs**:
```javascript
const links = svg.querySelectorAll('g[data-entity-1-uid][data-entity-2-uid]');

for (const link of links) {
  const sourceUID = link.getAttribute('data-entity-1-uid');
  const targetUID = link.getAttribute('data-entity-2-uid');
  // Find corresponding entities by UID
}
```

#### 3. Position Extraction

**Method 1 - Transform attribute**:
```javascript
const transform = group.getAttribute('transform');
const match = transform.match(/translate\(([^,]+),([^)]+)\)/);
if (match) {
  const x = parseFloat(match[1]);
  const y = parseFloat(match[2]);
}
```

**Method 2 - Shape coordinates**:
```javascript
const rect = group.querySelector('rect');
const x = parseFloat(rect.getAttribute('x'));
const y = parseFloat(rect.getAttribute('y'));

const circle = group.querySelector('circle, ellipse');
const cx = parseFloat(circle.getAttribute('cx'));
const cy = parseFloat(circle.getAttribute('cy'));
```

**Nested Transforms** (multiply matrices):
```javascript
function getAbsolutePosition(element) {
  let x = 0, y = 0;
  let current = element;

  while (current && current.tagName !== 'svg') {
    const transform = current.getAttribute('transform');
    if (transform) {
      const match = transform.match(/translate\(([^,]+),([^)]+)\)/);
      if (match) {
        x += parseFloat(match[1]);
        y += parseFloat(match[2]);
      }
    }
    current = current.parentElement;
  }

  return { x, y };
}
```

#### 4. Size Extraction

```javascript
const rect = group.querySelector('rect');
const width = parseFloat(rect.getAttribute('width'));
const height = parseFloat(rect.getAttribute('height'));

const ellipse = group.querySelector('ellipse');
const radiusX = parseFloat(ellipse.getAttribute('rx'));
const radiusY = parseFloat(ellipse.getAttribute('ry'));
// Width = radiusX * 2, Height = radiusY * 2
```

#### 5. Text Extraction

```javascript
const textElements = group.querySelectorAll('text');
const texts = Array.from(textElements).map(text => ({
  content: text.textContent.trim(),
  x: parseFloat(text.getAttribute('x')),
  y: parseFloat(text.getAttribute('y')),
  fontSize: text.getAttribute('font-size'),
  fontWeight: text.getAttribute('font-weight'),
  textAnchor: text.getAttribute('text-anchor')
}));
```

#### 6. Style Extraction

```javascript
const rect = group.querySelector('rect');
const fill = rect.getAttribute('fill') || 'white';
const stroke = rect.getAttribute('stroke') || 'black';
const strokeWidth = parseFloat(rect.getAttribute('stroke-width') || '1');
const strokeDasharray = rect.getAttribute('stroke-dasharray') || 'none';
const rx = parseFloat(rect.getAttribute('rx') || '0');
const ry = parseFloat(rect.getAttribute('ry') || '0');
```

#### 7. Shape Type Detection

```javascript
function detectShapeType(group) {
  if (group.querySelector('rect')) {
    const rect = group.querySelector('rect');
    const rx = parseFloat(rect.getAttribute('rx') || '0');
    return rx > 0 ? 'ROUND_RECTANGLE' : 'RECTANGLE';
  }

  if (group.querySelector('circle, ellipse')) {
    return 'CIRCLE';
  }

  if (group.querySelector('polygon')) {
    const polygon = group.querySelector('polygon');
    const points = polygon.getAttribute('points').trim().split(/\s+/);
    return points.length === 4 ? 'DIAMOND' : 'POLYGON';
  }

  if (group.querySelector('path')) {
    return 'PATH';
  }

  return 'UNKNOWN';
}
```

### Diagram Type Detection

#### Detection Algorithm

```javascript
function detectDiagramType(svg) {
  // Check for sequence diagram markers
  const participants = svg.querySelectorAll('g[data-participant]');
  if (participants.length > 0) {
    return 'SEQUENCE';
  }

  // Check for class diagram markers
  const classEntities = svg.querySelectorAll('g.entity[data-qualified-name]');
  if (classEntities.length > 0) {
    return 'CLASS';
  }

  // Check for activity diagram patterns
  const roundedRects = svg.querySelectorAll('rect[rx]');
  const diamonds = svg.querySelectorAll('polygon');
  if (roundedRects.length > 2 && diamonds.length > 0) {
    return 'ACTIVITY';
  }

  // Check for state diagram patterns
  const stateGroups = svg.querySelectorAll('g[id^="state_"]');
  const bullsEyes = Array.from(svg.querySelectorAll('circle')).filter(c => {
    const next = c.nextElementSibling;
    return next && next.tagName === 'circle';
  });
  if (stateGroups.length > 0 || bullsEyes.length > 0) {
    return 'STATE';
  }

  // Check for component diagram patterns
  // Look for component tabs (small rectangles outside main rectangle)
  const allRects = Array.from(svg.querySelectorAll('rect'));
  // More sophisticated detection needed...

  return 'UNKNOWN';
}
```

### Common Pitfalls

#### 1. Ignoring Nested Transforms

❌ **Wrong**:
```javascript
const x = parseFloat(rect.getAttribute('x'));
```

✅ **Correct**:
```javascript
const x = getAbsolutePosition(rect.parentElement).x +
          parseFloat(rect.getAttribute('x'));
```

#### 2. Not Handling Missing Attributes

❌ **Wrong**:
```javascript
const uid = group.getAttribute('data-entity-uid');
// uid could be null!
```

✅ **Correct**:
```javascript
const uid = group.getAttribute('data-entity-uid') || generateUID();
```

#### 3. Assuming Single Text Element

❌ **Wrong**:
```javascript
const label = group.querySelector('text').textContent;
```

✅ **Correct**:
```javascript
const textElements = group.querySelectorAll('text');
const primaryLabel = textElements[0]?.textContent || '';
const secondaryLabels = Array.from(textElements).slice(1)
  .map(t => t.textContent);
```

#### 4. Ignoring Visibility

Some elements may be hidden:
```javascript
const display = element.getAttribute('display');
const visibility = element.getAttribute('visibility');
const isVisible = display !== 'none' && visibility !== 'hidden';
```

#### 5. Not Handling CDATA Sections

Text may be wrapped in CDATA:
```xml
<text><![CDATA[special <chars> & symbols]]></text>
```

```javascript
const textContent = textElement.textContent.trim(); // Handles CDATA automatically
```

### Performance Optimization

#### 1. Use Specific Selectors

❌ **Slow**:
```javascript
const allGroups = svg.querySelectorAll('g');
const entities = allGroups.filter(g => g.hasAttribute('data-entity'));
```

✅ **Fast**:
```javascript
const entities = svg.querySelectorAll('g[data-entity]');
```

#### 2. Cache Queries

```javascript
class DiagramParser {
  constructor(svg) {
    this.svg = svg;
    this._entityCache = null;
    this._linkCache = null;
  }

  get entities() {
    if (!this._entityCache) {
      this._entityCache = Array.from(this.svg.querySelectorAll('g[data-entity]'));
    }
    return this._entityCache;
  }
}
```

#### 3. Build UID Index

```javascript
function buildUIDIndex(svg) {
  const index = new Map();
  const entities = svg.querySelectorAll('g[data-entity-uid]');

  for (const entity of entities) {
    const uid = entity.getAttribute('data-entity-uid');
    index.set(uid, entity);
  }

  return index;
}

// Fast lookup
const sourceEntity = uidIndex.get(sourceUID);
```

## Summary

### Key Takeaways

1. **PlantUML is Consistent**: Each diagram type generates SVG in a predictable, structured way
2. **Metadata is Rich**: Use `data-*` attributes for semantic information
3. **Groups are Semantic**: `<g>` elements represent logical entities, not just visual grouping
4. **IDs are Meaningful**: Pattern-based IDs help identify diagram elements
5. **Transforms are Hierarchical**: Always account for nested transformations
6. **Text is Structured**: Multiple text elements with different styling within entities

### Implementation Priority

For PlantEdit, implement parsers in this order:

1. **Activity Diagrams** (Simplest structure)
   - Clear node types (rounded rectangles, diamonds, circles)
   - Simple transitions
   - Good for testing parser architecture

2. **Class Diagrams** (Rich metadata)
   - Strong metadata (`data-entity`, `data-qualified-name`, UIDs)
   - Clear entity boundaries
   - Well-defined relationships with endpoint UIDs

3. **State Diagrams** (Similar to Activity)
   - Similar structure to activity diagrams
   - Additional composite state handling
   - Clear start/end markers

4. **Component Diagrams** (Moderate complexity)
   - Symbol-based detection
   - Interface lollipops require special handling
   - Package nesting

5. **Sequence Diagrams** (Most complex)
   - Different rendering architecture (no SVEK)
   - Time-based layout (vertical positioning matters)
   - Complex grouping (alt/opt/loop)
   - Participant tracking across entire diagram

### Testing Strategy

For each diagram type:

1. **Create minimal example** (2-3 elements)
2. **Generate SVG** with PlantUML
3. **Inspect structure** manually
4. **Write parser tests** based on actual output
5. **Iterate with complex examples**

This research provides the foundation for implementing accurate, maintainable parsers for PlantEdit.
